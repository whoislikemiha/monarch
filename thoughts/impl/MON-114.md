# MON-114 — P4b Slice C implementation notes

## What was implemented

Captain-visible execution-plan UI for P4b. The Quests tool now shows a separate
active-plan panel with manual add, rename, reorder, delete, start, complete,
skip, and block controls. The event log renders plan lifecycle events
distinctly, coherent actions show a plan-item chip when linked, and Agent View's
Now strip shows the active item plus the next plan slice from L2.

## Key decisions

- **Quest tool owns the manual panel, but not inside quest detail.** Plans are
  quest-scoped, so V0 lives at the top of the Quests tool for the active quest.
  Expanded quest rows stay focused on quest metadata and actual event history.
- **Reorder uses `db_set_plan`.** The UI sends the same items in a new order
  with stable ids; the backend preserves existing statuses on conflict.
- **Plan rows stay separate from timeline rows.** The panel is the intended
  route. The event log remains actual history, with chips linking actions back
  to plan items.
- **Browser-mode parity was completed.** The P4b plan commands had Tauri
  handlers but no WebSocket dispatch arms; Slice C adds them because all
  frontend IPC goes through `src/lib/api.ts`.
- **`plan_item_id` is now part of `QuestEventRow`.** SQLite already wrote the
  FK, but the row DTO omitted it, so the UI could not label linked actions.

  renderer, action plan chips.

- `src-tauri/src/ws.rs` — WebSocket dispatch for plan commands.
- `src/lib/bindings.ts` — regenerated after the DTO change.
- `AGENTS.md`, `ONBOARDING.md` — updated schema/status docs.

## Verification

- `npm test`

## What was left out

- Rich rationale editing and structured outcome/reason forms. V0 uses compact
  title editing and prompt-backed outcome/reason capture.
- Hierarchical plan rendering despite `parent_id` existing in schema.
- Chat-shadow or Architect plan manipulation; that remains P8 territory.
