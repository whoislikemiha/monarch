# MON-111 — P4b Slice A implementation notes

## What was implemented

Rust + SQLite foundation for durable per-quest execution plans (P4b). No sidecar tools or UI — those land in MON-112 / MON-113. Captain UI talks to the new commands directly, the executor will go through the InnerEvent → PersistCommand pipeline once Slice B emits the events.

## Key decisions

- **`set_plan` is bulk-replace, not diff.** Items with a matching id keep their status; missing items are deleted; new items start `pending`. Order comes from input array index. Diff-style mutations live in dedicated `add_plan_item` / `update_plan_item` / `delete_plan_item` commands.
- **One active item per quest.** Calling `start_plan_item(B)` while A is active silently resets A to `pending` (no event). Captures the invariant in code rather than via SQL constraints (partial UNIQUE indexes felt too clever).
- **No auto-advance on complete** (per Q4 in the plan). After `complete_plan_item`, L2's `active_plan_item_id` clears; captain or executor must explicitly `start_plan_item(next)`.
- **L2 sync via JSON extract.** `sync_plan_l2_tx` filters by `json_extract(payload_json, '$.currentQuestId')`, not `agents.current_quest_id`. This matters because `record_action_transition_internal` only updates the L2 payload, not the agents column — sticking to L2's own self-reported quest keeps tests cheap and behavior consistent across origin.
- **Action stamping reads live state.** `record_action_transition_internal` re-runs `recompute_plan_slice_tx` against `quest_plan_items` rather than trusting the loaded L2 snapshot — the slice may have shifted since the last L2 write.
- **Status transitions are advisory.** The DB doesn't reject e.g. blocking a `completed` item; the CHECK constraint just validates the final value. Stricter transitions can be a future refinement if the executor proves to need them.
- **`get_working_memory` was missing from the runtime Tauri handler** — drive-by fix, added alongside the new plan commands.

## Files touched

- `src-tauri/src/db.rs` — schema migrations, `WorkingMemoryPayload` v2, `PlanItemRow` + payload structs, 9 lifecycle methods, 4 helpers (`recompute_plan_slice_tx`, `sync_plan_l2_tx`, `insert_plan_event_tx`, `lookup_plan_item_tx`, validators), 10 Tauri commands, 11 unit tests.
- `src-tauri/src/sidecar_protocol.rs` — 5 new `InnerEvent` / `KnownInnerEvent` variants, `KNOWN_INNER_TAGS`, `From` impl, `apply_event` NoOp branches.
- `src-tauri/src/agent/persist.rs` — 5 new `PersistCommand` variants, `agent_id()` accessor, `apply` handlers, `build_persist_commands` dispatch, `inner_event_tag` mapping, `is_narration_tool` extension.
- `src-tauri/src/lib.rs` — both registries (`specta_builder` and `tauri::generate_handler!`) get the 10 new commands.
- `src/lib/bindings.ts` — auto-regenerated.

## What was left out

- **Sidecar narration tools and prompt block** — Slice B (MON-112).
- **Plan panel UI, timeline plan-item chips, Now strip extension** — Slice C (MON-113).
- **`update_plan` diff-style sidecar event** — bulk `set_plan` covers Slice B's needs; if the executor wants partial updates Slice B can introduce a `plan_diff` InnerEvent that lands here later.
- **Strict status transition guards** — see Decisions above.
- **Standalone "rebuild L2 from quest events on missing row" command** — `recompute_plan_slice_tx` runs on every plan-affecting op, and `#[serde(default)]` covers v1 payloads. A periodic rebuild path isn't needed for V0; deferred along with MON-107's broader L2 rebuild.
