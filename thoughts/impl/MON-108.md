# MON-108: P4 Slice B — Sidecar narration tools

## Summary

MON-108 wires P4 executor narration into the sidecar tool surface. The executor now has three semantic tools:

- `set_current_action(intent, previous_outcome?)`
- `complete_action(outcome)`
- `record_decision(decision, rationale?)`

The tools emit the MON-107 inner events that Rust already persists:

- `action_transition`
- `action_complete`
- `executor_decision`

## Implementation

Added `sidecar/src/narration-tools.ts` with a small `createNarrationTools(agentId, emit)` factory. Each tool:

- trims required text fields;
- normalizes blank optional fields to `undefined`;
- emits a semantic sidecar `event` envelope for Rust;
- returns a short tool result so Pi can continue naturally.

`RuntimeManager.createSession` registers these tools alongside `suggest_memory` through `customTools`.

`shadow-oath.ts` now includes action narration guidance in the system prompt. The guidance is intentionally taste-based:

- actions are meaningful chunks of work, not every read/grep/bash call;
- use `previous_outcome` when switching actions;
- use `complete_action` when done without starting the next action;
- use `record_decision` sparingly for explicit decisions, not hidden reasoning.

## Tests

Added `sidecar/tests/narration-tools.test.ts` covering:

- `set_current_action` emits `action_transition`;
- `complete_action` emits `action_complete`;
- `record_decision` emits `executor_decision` and omits blank rationale.
