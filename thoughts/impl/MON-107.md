# MON-107: P4 Slice A — Nested quest events and L2 working memory substrate

## Summary

MON-107 establishes the backend substrate for P4 executor narration:

- `quest_events` now supports nested timeline events through `parent_event_id`, semantic `author`, optional `surface_override`, and `payload_schema_version`.
- `agent_working_memory` stores L2 v0 as JSON keyed by `agent_id`.
- The sidecar protocol accepts narration events:
  - `action_transition`
  - `action_complete`
  - `executor_decision`
- The persistence queue turns those events into durable coherent actions, action outcomes, executor decisions, and nested tool-call child events.
- If an action transition arrives without a current quest, Rust auto-creates the active quest and emits the existing quest-created notifications.

## Data Shape

`agent_working_memory.payload_json` currently stores:

- `schema_version`
- `current_quest_id`
- `current_quest_path`
- `current_action`
- `recent_actions`
- `updated_at`

`current_action` points to the active top-level `coherent_action` quest event. Tool calls and decisions attach to that event by `parent_event_id`. Completing or transitioning away from an action updates the parent event payload, creates an `action_outcome` child, moves the action into `recent_actions`, and clears or replaces `current_action`.

Tool-call payloads intentionally store previews rather than full file contents or large command output. The canonical evidence remains in the underlying sidecar event log/messages; P4 Slice C can choose how much of that evidence to render.

## Persistence Flow

`agent/event_handler.rs` resolves the quest context before enqueueing persistence commands:

- `action_transition` uses the current quest or creates one from the action intent.
- tool start/end, memory suggestions, and executor decisions use the current quest if present.
- `action_complete` does not need a quest id because L2 points at the current action.

`agent/persist.rs` remains the single-writer path. It converts sidecar events into DB mutations and emits `quest-event-{quest_id}` updates after nested events change. Narration tool calls themselves are filtered out of tool-call child persistence so the timeline does not show `set_current_action` as work.
