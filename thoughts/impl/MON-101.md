# MON-101 — P2 Slice C: retrieval read path

Linear: [MON-101](https://linear.app/monarch-commander/issue/MON-101/p2-slice-c-retrieval-read-path-memories-surface-on-user-turn)
Plan: [thoughts/plan/MON-101.md](../plan/MON-101.md)

## What shipped

Memories now have a read path into future executor turns:

1. **Hybrid memory search in Rust.** `memory_search_for_agent(agent_id, query, top_k?)` runs FTS5 plus HNSW vector lookup, dedupes by memory id, and returns ordered `MemorySearchResult` rows. Hybrid hits rank first, then FTS-only hits, then vector-only hits. Retrieval is scoped to the active agent and silently returns empty when the embedder is not initialized.
2. **Access tracking.** Retrieved memory ids bump `access_count` and `last_accessed_at` through a small DB helper after final ordering.
3. **Sidecar request/response bridge.** Before a non-streaming prompt is forwarded to Pi, `runtime-manager.ts` emits `memory_search_request`. Rust handles it in `event_handler.rs`, calls the shared search helper, and responds with `memory_search_response`. The sidecar waits up to 200ms, then proceeds without injection if no response arrives.
4. **Prompt injection.** Non-empty results are prepended as a compact `## Relevant Memories` section. Plain-text prompts are prefixed directly; multimodal prompts keep their images and prefix the first text part.
5. **Docs and bindings.** `src/lib/bindings.ts` was regenerated, and `ONBOARDING.md` now lists the Keeper and memory-search protocol messages plus the updated memory status.

## Key decisions

- **Rust owns retrieval.** The sidecar does not read SQLite or embeddings. It only asks Rust for relevant rows, preserving the existing state-authority boundary.
- **Timeout over blocking.** Retrieval improves a turn when available, but the user message still moves if search is slow or disabled.
- **No injection during streaming follow-up.** Follow-up while `session.isStreaming` stays a direct `followUp()` path. This avoids mutating mid-turn context in a path that is already semantically "interrupt / add-on."
- **FTS query normalization.** The search helper tokenizes the free-form user prompt into a simple `OR` query to avoid FTS syntax failures from punctuation-heavy prompts.
- **Access count updates happen in the command path.** This is not sidecar event persistence, so it does not need the MON-37 single-consumer event pipeline.
