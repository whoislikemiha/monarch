# MON-104 — Stop button in ChatInput + roster pulse-stop affordance

Linear: [MON-104](https://linear.app/monarch-commander/issue/MON-104/stop-button-in-chatinput-roster-pulse-stop-affordance)
PR: [whoislikemiha/monarch#81](https://github.com/whoislikemiha/monarch/pull/81)
Plan: [thoughts/plan/MON-104.md](../plan/MON-104.md)

## What was implemented

Two new operator-facing entry points for aborting a running agent, both built on top of the existing `SidecarCommand::Abort` plumbing (no backend / sidecar / WS changes):

1. **ChatInput Send → Stop swap.** When `live.isStreaming` is true the primary action button in the composer renders as a danger-red Stop button in the same slot the Send button normally occupies. The textarea, attach button, and drag-drop handler all stay enabled so the operator can stage the next prompt; Enter is swallowed during streaming so a stray keypress can't queue or fire send.
2. **Roster pulse-dot becomes Stop on hover/focus.** The existing pulsing dot on each streaming `AgentRoster` pill is now wrapped in a `<button>` whose default visual is the same dot. On `.pill:hover` (mouse) or `.pill-pulse-stop:focus-visible` (keyboard) the dot fades out and a stop glyph fades in with a danger tint. Click and Space/Enter both `e.stopPropagation()` first so the pill's outer `selectAgent` handler is unaffected.
3. **Centralised `abortAgent(agentId)` in `liveAgentStore`.** Any component can now dispatch abort against any agent without owning the sidecar wire path. AgentRoster uses it directly; AgentView still owns its own local `abort()` because it lives next to the rest of the per-view command surface.

The existing `AgentPortrait` abort button is unchanged — kept as a third entry point.

## Key decisions

- **`streaming` + `onabort` props on ChatInput, not a single `disabled` flag.** Splitting the concept lets the composer keep textarea/attach editable during streaming while still flipping the action button. The old `disabled` prop was the only thing wired to `isStreaming` in `AgentView`, so removing it wasn't a backwards-compat concern.
- **Drag-drop unblocked while streaming.** The plan only mentioned attach button + textarea staying enabled; I extended this to the drag-drop handler in `AgentView` for consistency. The existing `if (isStreaming) return;` rationale ("input is disabled") no longer holds.
- **Hover-only on the roster (with keyboard focus parity).** The danger tint only appears when the pointer or focus is on a specific streaming agent — a row of streaming agents doesn't look like a row of warnings.
- **Same store action, two callers.** `abortAgent` is a free function alongside `seedFromSnapshot` / `applyUpdate` / `removeLiveState`, matching the existing module shape rather than introducing a method on the store object.
- **Errors swallowed in `abortAgent`.** Abort is fire-and-forget; the canonical signal that it worked is `isStreaming` flipping back to false from a sidecar `agent_end`. Errors are logged for debugging only.

## Files touched

- `src/lib/ChatInput.svelte` — new `streaming` + `onabort` props; conditional Send/Stop render; stop-btn CSS; drop the stale `chat-input.disabled` rule and "Agent is working..." placeholder; Enter swallowed while streaming.
- `src/lib/AgentView.svelte` — pass `streaming={isStreaming}` + `onabort={abort}` to ChatInput; drop the streaming guards from `handleDragOver` / `handleDrop`.
- `src/lib/AgentRoster.svelte` — wrap the pulse dot in a `<button class="pill-pulse-stop">`; add hover/focus CSS that swaps dot ↔ stop glyph; import `abortAgent`.
- `src/lib/toolbox/liveAgentStore.svelte.ts` — new `abortAgent(agentId): Promise<void>` exported alongside the existing free functions.

## What was left out

- No queueing of the staged prompt — pressing Enter while streaming is a no-op, the operator presses Send themselves once the agent is idle.
- No right-click context-menu Stop on the roster (chosen gesture was the hover icon).
- No "stop all" / bulk-stop on the roster.
- No changes to background work (Keeper / compaction) — only the foreground assistant turn.
