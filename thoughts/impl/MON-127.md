# MON-127 — Proper chat history: implementation notes

PR: https://github.com/whoislikemiha/monarch/pull/107

## What was implemented

Real multi-session support per agent. "New session" now actually starts a clean
conversation; a "Sessions" dock panel lists past sessions with titles/previews,
shows any session read-only, and can rename/continue them. The session
semantics are now three explicit moves (fresh / continue-in-place /
continuation-with-ancestry), documented in ONBOARDING.md §"Session ancestry".

## Key decisions

- **Root cause of "new session does nothing"**: the frontend chained
  `parent_session_id` to the previous session, and ancestry walks made the new
  session inherit everything. Fresh sessions are now parentless, full stop.
- **Rust owns the reset.** `new_session`/`switch_session` call
  `rebuild_state_from_session` themselves, so a stale `get_agent_state` seed
  can never resurrect the old conversation. Frontend just remounts.
- **Waking is not a conversation boundary.** `spawnStoppedAgent` reuses the
  agent's current session row (replaying its chain via `sourceSessionId`)
  instead of minting a parent-chained row per wake. `fresh: true` is the
  explicit clean-slate wake used by "new session" on sleeping agents.
- **Browser shows per-session messages** (`get_session_display_items`, no
  ancestry walk); the active chat after a continue shows the flattened chain —
  that is what the agent remembers.
- **Surface lives in the panel registry** (the v2 dock), not the legacy
  toolbox registry — the toolbox isn't mounted in the v2 shell. Registered in
  both for completeness.
- **Titles**: nullable `sessions.title` column; display falls back to a
  derived first-user-message snippet computed in `db_list_session_summaries`.

## Bugs found and fixed along the way

- Sidecar `createSession` destroy-on-replace emitted `session_destroyed` →
  Rust forwarded `agent-exit` → frontend marked healthy agents **stopped** and
  toasted "Sidecar exited (code null)" (wire payload is the *string* `"null"`,
  which passed the `!= null` guard). Replace is silent now; the toast guard
  parses numerically.
- Chat-pane turn membership (`chatStore`) now resets on new/switch session —
  ordinals are positions in the old conversation and misrouted new turns.
- Header "New chat" added a pane on the same live Pi session (scoped-chat
  machinery) — reads as a broken new session; it now starts a real one.

## What was left out

- Paged/infinite-scroll loading inside one conversation (separate issue).
- Cross-agent full-text search over history.
- Session deletion/archiving from the browser (rename only).
- Historical DBs keep their old per-wake "continued" session rows — accurate
  to how they were created, just clutter.
