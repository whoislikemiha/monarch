# MON-102 — Executor `suggest_memory` tool

Linear: [MON-102](https://linear.app/monarch-commander/issue/MON-102/p2-executor-suggest-memory-tool-keeper-input-firewall)

## What shipped

The executor now gets a Monarch-internal `suggest_memory(title, summary, content)` Pi custom tool on every sidecar session. Tool execution emits a `memory_suggestion` inner event through the existing sidecar event envelope; Rust recognizes it as a typed `InnerEvent`, logs it to the forensic `events` table, and records a `quest_events` row only when `agents.current_quest_id` is set.

The Quest Timeline renders `memory_suggestion` rows with a distinct card showing title, summary, and expandable details. The Memory Inspector remains untouched because this path never writes to `memories`.

## Implementation notes

- `sidecar/src/runtime-manager.ts` registers the tool via `createAgentSession({ customTools })`; no extension discovery or agent-local extension loading is involved.
- `sidecar/src/protocol.ts` documents the `memory_suggestion` inner event shape.
- `src-tauri/src/sidecar_protocol.rs` mirrors the event with `InnerEvent::MemorySuggestion` and treats it as `ApplyOutcome::NoOp` for live chat state.
- `src-tauri/src/agent/event_handler.rs` resolves `agents.current_quest_id` before enqueueing persistence for the suggestion.
- `src-tauri/src/agent/persist.rs` appends `RecordQuestEvent { event_type: "memory_suggestion" }` through the existing single-consumer pipeline. If no current quest exists, the suggestion is logged as a normal event but no quest row is created.
- `ONBOARDING.md` now calls out `memory_suggestion` as a Monarch-authored inner event and quest event kind.

## Firewall check

Verified by code search: `memory_suggestion` only routes to `RecordQuestEvent`; the memory write path still goes through `PersistCommand::InsertMemory` / `insert_memory_internal` from Keeper and debug smoke paths. There is no direct `memory_suggestion` → `memories` write path.
