# MON-116 — P5 Slice A implementation notes

## What was implemented

Backend/data foundation for P5 rich quests:

- `quest_nodes` now has rich what/why fields: `scope`, `current_direction`,
  `rationale`, and `fork_parent_id`.
- `quest_refs` stores external quest references such as Linear tickets, GitHub
  issues/PRs, files, URLs, and artifacts.
- `QuestRow` and exported bindings include the new metadata.
- New manual-editor commands update semantic quest fields and emit
  timeline-visible quest events for scope, direction, rationale, grade, and
  summary changes.
- New manual event command records `note`, `blocker`, `blocker_resolved`,
  `question`, and `answer` rows.
- New quest-ref commands list/create/update/delete references.
- WebSocket dispatch has parity with the Tauri command path.

## Key decisions

- **Existing status enum stays canonical.** MON-83 already constrained status
  to `pending`, `in_progress`, `claimed_done`, `verified`, `disputed`,
  `ambiguous`, `done`, `abandoned`, and `superseded`. P5 Slice A does not try
  to retrofit the design-doc `blocked`/`paused` names into that CHECK
  constraint; blockers are event rows in this slice.
- **Manual quest updates are separate from generic updates.** `db_update_quest`
  remains the direct patch path for older callers. `db_update_quest_manual`
  is the P5 path that records semantic timeline events.
- **Quest refs are flexible strings.** `ref_type` is not CHECK-constrained so
  the next UI slice can add kinds without another migration.
- **Reference notifications use `quest-refs-{questId}`.** The next frontend
  slice can subscribe/refetch without overloading quest event channels.
