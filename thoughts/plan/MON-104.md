# MON-104 — Stop button in ChatInput + roster pulse-stop affordance

Linear: [MON-104](https://linear.app/monarch-commander/issue/MON-104/stop-button-in-chatinput-roster-pulse-stop-affordance)

## Summary

Aborting a running agent is already plumbed end-to-end — the sidecar honours
`SidecarCommand::Abort`, Rust forwards it through the same `send_command` path
as a normal user message, the frontend has an `abort()` helper in
`AgentView.svelte`, and `LiveAgentState.is_streaming` is the canonical "agent
is producing a turn" signal that the UI already reacts to. The only place an
operator can actually invoke abort today is a danger button hidden inside the
`AgentPortrait` command menu. This issue adds two more entry points where the
operator's eyes already are: the Send slot in `ChatInput` (Send becomes Stop
while streaming, then flips back), and the streaming pulse dot on each
`AgentRoster` pill (turns into a clickable Stop on hover/keyboard focus
without changing the pill's existing select-on-click contract). The existing
`AgentPortrait` abort button is left alone.

- `src-tauri/src/agent/commands.rs:75` — Tauri `send_command` IPC entry.

- `src-tauri/src/agent_state.rs:189` — `is_streaming` flips false on `AgentEnd`; this is what drives both the chat composer's mode swap and the roster pulse.
- `sidecar/src/runtime-manager.ts` — already handles the abort command; on abort the sidecar emits `agent_end` (or equivalent terminal event) so `is_streaming` returns to false and the partial assistant turn is finalised by the existing persist path. Trust this; do not re-implement.

## What needs to change

### 1. ChatInput becomes streaming-aware

`ChatInput` currently has one `disabled` prop driven by `isStreaming` and uses
it for the textarea, the attach button, *and* to gate the Send button. We need
to split that mental model:

- Introduce two distinct concepts on `ChatInput`'s prop surface: **streaming**
  (the agent is producing a turn — show Stop, hide Send) and **not-allowed**
  (some other reason input is disabled, e.g. archived agent — currently this
  case is implicit and may not actually exist). The minimum-viable shape is to
  add a `streaming: boolean` prop plus an `onabort: () => void` callback, and
  decouple the textarea/attach disabled state from `isStreaming`.
- While `streaming` is true: the primary action button in the Send slot
  renders as Stop (square/⏹ icon, danger accent), is always enabled, and on
  click invokes `onabort`. Send is not rendered.
- While `streaming` is false: existing Send behaviour, gated by
  empty-text/no-images.
- The textarea stays editable while streaming (operator can compose the next
  prompt). The placeholder should not say "Agent is working..." in this
  branch — pick a neutral message-prompt placeholder.
- The attach button: also stays enabled while streaming (the operator is
  staging the next prompt). This is consistent with leaving the textarea
  editable.
- `handleKeydown()`: pressing Enter while streaming must NOT trigger abort and
  must NOT send. Recommended behaviour is to ignore Enter (do nothing) while
  streaming so the user has to click Stop deliberately. See open questions.

### 2. AgentView wires the new ChatInput contract

`AgentView.svelte` stops passing `disabled={isStreaming}` and instead passes
`streaming={isStreaming}` plus `onabort={abort}` (the existing `abort()`
function defined at line ~378). No new logic needed here — abort already
dispatches the sidecar command via `sendPiCommand({ type: "abort" })`.

### 3. AgentRoster pulse dot becomes a hover-revealed Stop

The pulse dot at `AgentRoster.svelte:214` is currently a non-interactive
`<span class="pill-pulse-dot">`. The change:

- Wrap the dot in a `<button>` (only when `streaming` is true) with
  `aria-label="Stop {agent.name}"`, `tabindex="0"`, an `onclick` that calls
  `e.stopPropagation()` *first* (mirror the dismiss/summon pattern on
  lines 221, 230), then fires the abort command for that agent.
- The visual behaviour, all in CSS:
  - Default state when not hovering the pill: the button is the existing
    pulsing dot — same animation, same visual.
  - When the pill is hovered (`.pill:hover .pill-pulse-stop`), the dot fades
    out and a stop icon (square or ⏹) fades in inside the same slot, with a
    danger-tinted hover ring/background to communicate the destructive action.
  - On keyboard focus of the button (`.pill-pulse-stop:focus-visible`), reveal
    the stop icon the same way so keyboard users get the same affordance.
- The button only renders when `streaming` is true. When the agent stops, the
  button vanishes and the pill's status row reverts to its idle layout.
- The pill's outer `onclick={() => agentStore.selectAgent(agent.id)}` and
  `onkeydown` Enter handler stay as-is. The button's `e.stopPropagation()`
  ensures clicking the stop icon doesn't also select the agent.

### 4. Dispatching abort from the roster

The roster doesn't currently have access to an `abort` function. Two
reasonable shapes:

- **a.** Surface an `abort(agentId)` action from `liveAgentStore` (or a thin
  helper module) so any component can dispatch abort against any agent
  without going through the active agent's `AgentView`. This is the cleaner
  shape because the roster operates across all agents, not just the active
  one.
- **b.** Plumb a `onabort={(agentId) => …}` callback prop through
  `AgentRoster` from `App.svelte` and have `App.svelte` (or a small helper)
  call `api.ts` directly.

(a) is preferred because it keeps `AgentRoster.svelte` simple and matches
how the roster already reaches into per-agent state via the store.

### 5. Verification

- Manual: start an agent, send a long prompt, confirm Stop replaces Send in
  ChatInput, click it, confirm `is_streaming` flips back, send another
  prompt, confirm the agent works without restart.
- Manual: while an agent (active or background) is streaming on the roster,
  hover its pill, confirm the pulse becomes the stop icon, click it, confirm
  the agent stops and the roster pill reverts to idle. Confirm clicking
  elsewhere on the pill still selects the agent and does NOT stop it.
- Manual: tab to the streaming pill, focus the stop button, press Space —
  confirm abort fires.
- Manual: confirm the existing `AgentPortrait` abort button still works.
- Type-check: `npx svelte-check` clean.
- Backend: no Rust changes expected, so `cargo check` should be a no-op
  beyond unrelated drift.

## Open questions

1. **Enter key while streaming.** Should pressing Enter in the textarea while
   the agent is streaming (a) do nothing (recommended — Stop must be a
   deliberate click), (b) trigger Stop, or (c) queue the prompt for after the
   current turn? Queueing is out of scope per the issue, so the choice is
   really (a) vs (b). I recommend (a).

2. **Attach button while streaming.** Same question for image attachments —
   stay enabled (so the operator can stage the next prompt fully) or stay
   disabled? I recommend enabled, matching the textarea decision; surface if
   disagreed.

3. **Roster stop dispatch shape — store action vs prop callback.** Section
   "4. Dispatching abort from the roster" lists the two options. Going with
   (a) (action on the store / helper) unless you prefer the prop callback
   shape for consistency with how `ondismiss` / `oneditproject` are wired
   today.

4. **Stop icon glyph and danger tint.** Use the same icon and red used by the
   existing `AgentPortrait.svelte` abort button for consistency, or
   intentionally pick a smaller/quieter look so the roster doesn't feel
   alarming when many agents are running? Recommend matching the portrait
   for the ChatInput stop, and using a slightly muted variant for the roster
   stop so a stack of running agents doesn't look like a stack of warnings.

5. **Hover-only on the roster — discoverability for trackpad-less users.**
   The hover-reveal works on macOS trackpads but is invisible on touch /
   keyboard until focused. Keyboard focus-visible covers keyboard users.
   Touch is not a real Monarch use case today, so I think it's fine to
   accept hover-only for pointer users. Flag if disagreed.

## Out of scope

- Any change to the existing `AgentPortrait` abort button.
- New backend semantics for abort — the existing
  `SidecarCommand::Abort` path is reused untouched.
- Queueing or staging the next prompt to auto-send when the current turn
  ends. Only the textarea's text is preserved; the operator presses Send (or
  Enter) themselves once the agent is idle.
- Right-click context-menu Stop on the roster (the hover icon is the chosen
  gesture).
- Stopping background work like the Keeper / compaction worker (MON-100) —
  only the foreground assistant turn.
- Multi-agent "stop all" or roster bulk-stop.
- Any persistence-layer work (partial-turn finalisation already happens via
  the existing sidecar abort → `agent_end` → persist pipeline).
