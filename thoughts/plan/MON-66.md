# MON-66 — Archive shadows instead of deleting

Linear: https://linear.app/monarch-commander/issue/MON-66

## Summary

Today the sidebar shows every agent ever extracted because `db_get_agents` returns all rows unconditionally. The X button on an agent row kills the sidecar and removes the agent from the in-memory session list, but never touches the DB — so the agent reappears on next startup, dimmed as "standby". The operator-visible symptom is "why are all my old shadows here?".

The fix is to introduce **archive** as a first-class lifecycle state. A new nullable `archived_at` column on the `agents` table distinguishes active from archived shadows without deleting rows. The default sidebar view surfaces only active shadows. An Active / All toggle lets the operator see archived shadows inline (greyed out) and right-click → "Summon back" to resurrect them. Shadow identity, sessions, experience, and stats all persist unchanged across the archive/unarchive cycle.

No code path deletes DB rows. The existing `db_delete_agent` command is out of scope for this work but flagged for audit (see Open Questions).

## What needs to change

### 1. DB migration (conceptual)

- Extend the `agents` table with a nullable ISO-timestamp column (`archived_at TEXT NULL`). NULL means active; any timestamp means archived. Timestamp is preferred over a boolean flag because it preserves the *when*, which is useful for sorting in the All view and for future "recently dismissed" UI.
- Add the `ALTER TABLE` in the same silent-ignore pattern as `context_window` so existing DBs migrate forward on next launch.
- Extend `AgentRow` struct in Rust and the corresponding TS binding with the new optional field.

### 2. Backend commands (conceptual)

- Extend `db_get_agents` with a flag to include archived rows (e.g. `include_archived: bool`, default false). This keeps one command rather than two, simpler for the frontend toggle. Default call signature stays compatible after bindings regenerate (default false at the Rust layer).
- Add `db_archive_agent(agent_id)` — sets `archived_at = CURRENT_TIMESTAMP`.
- Add `db_unarchive_agent(agent_id)` — sets `archived_at = NULL`.
- Register all three (new + modified) in `lib.rs` `generate_handler!`. Mirror the three in `ws.rs` `dispatch_command`.
- Regenerate `bindings.ts` via `cargo run -- --export-bindings`.

### 3. Frontend — loading and filtering

- `loadSavedAgents()` passes `include_archived: sidebarShowAll` to `db_get_agents`. The agent array gets both active and archived rows when All mode is on; only active when Active mode is on. `activeTabId` defaulting logic stays as-is (first agent) because it already guards against `length === 0`.
- Add an `archivedAt?: string` (or `isArchived: boolean`) field on the `Agent` type, populated from the DB row. Agents created in-session via `createAgent` start active (`archivedAt: undefined`).

### 4. Frontend — Dismiss flow (replacing current kill)

- The X button opens a small modal that confirms "Dismiss [shadow name]?" with explanatory copy ("Conversation history and stats are preserved. You can summon them back later."). Reuse the existing modal pattern (`role="dialog"` + overlay + Escape-closes).
- On confirm: kill sidecar (existing `kill_agent` Tauri command) → archive in DB (new `db_archive_agent`) → remove from local `agents` array → close tab if open.
- Copy changes: button tooltip `Dismiss`, confirm dialog title and action labels match.

### 5. Frontend — Sidebar toggle

- Add an Active / All segmented control to `Sidebar.svelte` header area. State lifted to `App.svelte` as a new reactive variable `sidebarShowAll` (default false), persisted via the existing `db_set_ui_state` / `db_get_ui_state` mechanism (same shape as `sidebarCollapsed`).
- When `sidebarShowAll` flips: re-run `loadSavedAgents()` (or fetch archived on demand and merge) so the sidebar has the full roster. Simpler: always fetch all when toggle is All, fetch only active when toggle is Active.
- Archived agents render with an additional CSS class (`class:archived`) that dims them more aggressively than standby and is visually distinct enough to signal "not currently in the roster".

### 6. Frontend — Summon back

- `Sidebar.svelte` right-click menu gains a conditional "Summon back" item when the clicked agent is archived. Wired through a new `onsummon` callback prop from the sidebar to App.svelte, mirroring the existing `onsavetemplate` / `onkill` pattern.
- On summon: call `db_unarchive_agent` → update the agent's local `archivedAt` to undefined → the agent is now in the active list. If the operator is in Active mode, it stays visible; if in All mode, it moves visually from archived to active styling.

### 7. Docs

- Update `CLAUDE.md` key files table if any new top-level file is added (none expected).
- Update `ONBOARDING.md` data model section to mention `archived_at` as part of the `agents` schema.

## Decisions locked in

1. **Column** — `archived_at TEXT NULL` (ISO timestamp). Preserves the *when*.
2. **Commands** — two: `db_archive_agent(id)` and `db_unarchive_agent(id)`. Readable at call sites.
3. **List query** — extend `db_get_agents` with `include_archived: bool` flag (default false). One command, backwards-compatible via regenerated bindings.
4. **Permanent delete** — **in scope**. Right-click menu exposes "Delete permanently" (visually distinct, red) with its own confirmation dialog separate from Dismiss. `db_delete_agent` is the backing command; no other path in the UI invokes it.
5. **Dismiss dialog copy** — plain and factual: "Dismiss [name]?" with supporting copy noting history and stats are preserved. No lore.
6. **Delete dialog copy** — plain and factual but firmer: "Permanently delete [name]?" with a clear irreversible warning.
7. **Toggle placement** — **top of sidebar**, next to the `+` button. Segmented control with Active / All.
8. **Kill idempotency** — verify `agent.rs:806-816` no-ops when the agent is already stopped; fix defensively if not.

## Implementation phases

Planned as three commits for clean reviewability.

### Phase 1 — Backend: schema + commands

- Add `archived_at` column via `ALTER TABLE` in `Database::new()` migration block.
- Add `archived_at: Option<String>` to `AgentRow` struct.
- Add `archive_agent_internal`, `unarchive_agent_internal` DB methods.
- Modify `get_agents_internal` to accept an `include_archived: bool` argument.
- Add `db_archive_agent`, `db_unarchive_agent` Tauri commands; update `db_get_agents` signature.
- Register all three in `lib.rs` `generate_handler!`.
- Mirror in `ws.rs` `dispatch_command`.
- Regenerate `bindings.ts`.
- `cargo check` clean; no frontend changes yet.

### Phase 2 — Frontend: dismiss + sidebar filter + toggle

- Add `archivedAt?: string` to `Agent` frontend type.
- `loadSavedAgents()` threads `include_archived: sidebarShowAll` to `db_get_agents`.
- New `sidebarShowAll` state on `App.svelte`; persist via `db_set_ui_state` like `sidebarCollapsed`.
- Replace current X-button behavior: confirm dialog → `kill_agent` → `db_archive_agent` → remove from `agents` array → close tab.
- Add segmented Active / All control at the top of the sidebar (next to `+` button).
- Add `class:archived` visual state in `Sidebar.svelte` — dimmed and visually distinct from current `.standby`.
- Update button tooltip copy: "Dismiss".

### Phase 3 — Frontend: unarchive + permanent delete via context menu

- Extend right-click menu in `Sidebar.svelte`:
  - Always available: "Save as template" (existing), "Delete permanently" (new, red).
  - When agent is archived: replace the dismiss/kill button behavior with "Summon back" too.
- Wire `onsummon` and `ondeletepermanent` callbacks from sidebar to App.svelte.
- On summon: call `db_unarchive_agent` → clear `archivedAt` locally.
- On delete: confirm dialog (separate, irreversibly-worded) → `kill_agent` (if running) → `db_delete_agent` → remove locally.
- Verify `kill_agent` idempotency during testing; file a tiny follow-up commit on this branch if a defensive guard is needed.

## Out of scope

- Bulk archive / multi-select
- Auto-archive of long-idle agents
- Archive search, filtering by date, or bulk views
- "Stop sidecar without archiving" as a distinct UI action
- Syncing archive state to external systems (Linear, remote instances)
