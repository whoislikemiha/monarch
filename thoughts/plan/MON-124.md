# MON-124 — Flesh out the workspace timeline into a real execution timeline

## Summary

The ui-v2 workspace shipped the 50/50 timeline‖chat split, but the timeline pane (`TimelinePane.svelte`) is a thin projection of L2 working memory: a NOW strip plus the last ≤10 completed actions as flat one-liners. There is no scrollable history, no drill-in to the tool calls under an action, no artifacts, and raw tool tables still render in every chat pane — contradicting the locked two-surface design (attention.md: chat = dialogue only; timeline = the work, action-shaped). The backend already records everything needed: `objective_events` is a complete forensic spine — `coherent_action` rows with `action_outcome`/`tool_call`/`executor_decision` children via `parent_event_id`, plan events, status changes, `plan_item_id` stamping — with live `objective-event-{id}` pings on both write paths (verified: `record_tool_call_end_internal` notifies too). This issue makes the timeline the primary observability surface: paginated infinite history across objective boundaries, drill-in action cards with live merge and artifact chips, full plan + objective context, the event-icon visual system with the 4 backport fixes, and chat de-tooling. The work is ~85% frontend; the Rust slice is one new feed query plus two small payload/event additions.

## What needs to change

### 1. Backend feed + pagination (the only Rust slice)

- New read command `db_list_agent_timeline(agent_id, before_cursor, limit)`: joins `objective_events` to the agent's objectives via `objective_nodes.assignee_shadow_id`, pages on **top-level** events (`parent_event_id IS NULL`) newest-first with a `(created_at, id)` cursor, then fetches children for just that page in a second query. Returns top-level rows + children + enough objective metadata (id, title path, status) to render segment headers without N extra round-trips.
- `record_tool_call_start_internal` additionally writes a normalized `target` into the tool_call payload, extracted from the full args while they're available (path-like arg for read/write/edit/list_directory, command string for bash; best-effort for unknown tools). Payload-only change; no schema migration; bump `payload_schema_version` if warranted.
- New `chat_spawned` event type recorded when a scoped chat opens on an action: child of that action's event, payload carrying scope id/label, author `captain`. Reuses the existing manual-event recording path and notification plumbing.
- Registration: Tauri handler list, specta binding export, WebSocket dispatch mirror.

### 2. Timeline store + historical spine + infinite scroll

- A paged per-agent timeline store (sibling to `objectiveStore`, which keeps serving the dock inspector): ordered page list, append-only backwards, grouped top-level entries with typed children, segment boundaries where `objective_id` changes. Preload ~20 top-level entries; IntersectionObserver sentinel at the old end loads the next page.
- Live reconciliation: `objective-event-{id}` pings refresh the newest page / patch the affected event; working memory keeps powering only the NOW strip.

### 3. Action cards — drill-in, live merge, artifacts

- `TimelineAction` becomes a card: weighted headline icon, intent, relative time; collapsed body shows outcome + child-count summary; expanded body renders a **heterogeneous typed child list** (tool calls as mono data-rows with target/duration/status, decisions with rationale, closing outcome line; future delegated-run groups slot in here — the Arc II seam).
- Active card auto-expands, ticks elapsed time, and merges `liveAgentStore.toolExecutions` over persisted children by `toolCallId` (persisted row wins once the ping lands).
- Artifact chips in the card footer: files touched (distinct `target`s of mutating tools), chats spawned (`chat_spawned` children; click refocuses the open pane or re-opens a scoped pane with the same context).
- Unnarrated-work fallback: orphan tool_call events / live executions with no current action render under a synthesized "working…" group so activity never disappears.

### 4. NOW region — plan block, objective reference, no-objective state

- `NowStrip` grows the full collapsible PLAN block (all items with done/now/next/skipped/blocked states + progress fraction), keeps the active/next peek when collapsed.
- Objective reference: path + status chip in the strip header; designed quiet "conversational — no objective" state instead of rendering nothing.

### 5. Event-icon system + 4 backport fixes

- Adopt the unused `.evt`/`.ei` atoms as a typed `EventIcon` primitive in `src/lib/ui/` with one glyph per event kind (action, tool, outcome, decision, plan, status, note, blocker, chat, report). Differentiate by shape, reuse existing tone tokens.
- Apply the carry-in fixes: weighted headline-action glyph; decision glyph must not be a diamond (reserved for objective nodes); per-depth indent + guide generalized past 2 levels; path values left-aligned with head truncation so the tail survives.

### 6. Milestones + report card in-stream

- Thin interleaved rows for plan_created/plan_changed, plan_item_started/completed/skipped/blocked, notes/blockers/questions; status_change renders as a section divider ("objective started" / "objective done · grade B").
- When a segment's objective closes, an inline report card renders from `objective_reports`: summary line, grade chip, expandable decisions/learned/artifacts/open threads.

### 7. Chat de-tooling

- `MessageStream`'s tool-group branch renders a one-line activity chip ("worked · N tool calls · view in timeline") instead of `ToolGroupBlock`; clicking scrolls the timeline to the corresponding action card and flashes it. The chip needs a tool-group → action-event correlation (by toolCallId membership) with a graceful no-link fallback.
- This also fixes tool-groups leaking into every scoped pane, since the tables stop rendering in chat entirely.

## Build sequence (slices, each independently testable)

1. **Backend feed + payload additions** — `db_list_agent_timeline`, `target` extraction, `chat_spawned` recording; bindings regenerated. Test: invoke from devtools, pages come back across objectives.
2. **Historical spine + infinite scroll** — paged store, segment headers, sentinel loading. Test: scroll past 20 entries and across an objective boundary.
3. **Card depth** — typed children, live merge, artifact chips, unnarrated fallback. Test: watch a tool tick running→done inside the active card; open a scoped chat and see the chip persist after closing the pane.
4. **Plan block + NOW polish** — full plan, objective reference, no-objective state. Test: agent with a 5-item plan shows all states; fresh agent shows the conversational state.
5. **Event icons + backport fixes** — visual system. Test: against `?catalog` and a deep objective tree.
6. **Milestones + report card** — in-stream rows + close-of-objective report. Test: close an objective, the segment ends with the report.
7. **Chat de-tooling** — chips replace tables. Test: chat shows dialogue only; chip click lands on the right card.

## Open questions

1. **Feed completeness vs. assignee join** — objectives created manually without an assignee (or pre-P1 rows) won't appear in an `assignee_shadow_id`-joined feed. Acceptable for the single-shadow arc, or should the feed also union objectives reached via `agents.current_objective_id` history? (Recommendation: assignee join only; it's what auto-creation writes.)
2. **Where chat_spawned recording lives** — frontend calls the existing `db_record_objective_event` command on `openScopedPane` (simplest, no new Rust), or a dedicated command that validates the parent action exists. (Recommendation: reuse the existing command with the new event type.)
3. **Old events without `target`** — pre-existing tool_call rows only have `args_preview`. Render their data-rows with a best-effort parse or just the tool name? (Recommendation: tool name + preview snippet; no fragile parsing.)
4. **Chip → action correlation for old turns** — tool-groups in `LiveAgentState` don't carry event ids; correlation by toolCallId works for the current session but may miss replayed history. Acceptable to show a non-linking chip for those?
