# MON-119 — P6 Slice A research plan

## Summary

Land the backend substrate for P6 first-person quest reports. After this slice
Monarch has a `quest_reports` table, an ordered persistence variant for writing
into it via the existing single-consumer pipeline (MON-37), and Tauri commands
the captain UI (Slice C) and tests can use to insert and fetch reports.

Both the sidecar `complete_quest(report)` tool (Slice B) and any later
manual-edit path will route through the persistence variant added here. No
caller produces reports in this slice — that's Slice B. We are only landing
the data contract, the write path, and the read commands, so the rest of the
phase has somewhere to attach.

## What needs to change

### Schema

A new `quest_reports` table inside the migration block at the end of
`init_schema`, placed after `memory_keeper_runs` since it forward-references
that table:

- **`id`** — text primary key (UUIDv4, matching `quest_refs` / `quest_events`
  conventions).
- **`quest_id`** — `TEXT NOT NULL REFERENCES quest_nodes(id) ON DELETE CASCADE`.
  When a quest is deleted, the report should go with it.
- **`agent_id`** — `TEXT REFERENCES agents(id) ON DELETE SET NULL`,
  denormalized from `quest_nodes.assignee_shadow_id` at write time. The
  report is fundamentally an artifact of the shadow that ran the quest;
  carrying the FK directly makes per-agent report queries (and the future
  cross-agent project view in P9) one table instead of a JOIN.
  `SET NULL` matches the lossy-preserved pattern `quest_nodes` already
  uses for assignee — agent archive nulls the attribution without
  deleting the report.
- **`payload`** — `TEXT NOT NULL` holding the structured JSON
  (`summary`, `outcome`, `decisions`, `learned`, `artifacts`, `open_threads`,
  `reflection`, `grade`). Slice A treats this as an opaque blob; Slice B
  defines the schema via the tool argument shape.
- **`created_at`** — `TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))`.
- **`updated_at`** — `TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))`.
  Bumped on upsert so the Keeper / UI can detect revisions.
- **`distilled_by_keeper_run_id`** — `INTEGER REFERENCES memory_keeper_runs(id) ON DELETE SET NULL`,
  nullable. Slice D backfills this when the Keeper consumes the report.
- **`UNIQUE (quest_id)`** — one report per quest. Slice B's
  `complete_quest(report)` is upsert semantics (revisions replace).
- Index: implicit via the unique constraint; no extra index needed.

### Persistence pipeline (MON-37)

A new `PersistCommand::WriteQuestReport { agent_id, payload }` variant in
`src-tauri/src/agent/persist.rs`. Mirrors `RecordQuestEvent`:

- New `WriteQuestReportPayload` request DTO (Serde/Specta-derived).
- Variant added to the enum.
- Arm added in `agent_id()`.
- Arm added in `apply()` that calls `db.write_quest_report_internal(payload)`
  and then emits on `quest-report-{quest_id}` via `agent::emit_event`.

No producer of this variant lands in Slice A — `event-handler.rs` is
untouched. Slice B will add the producer when it wires the
`complete_quest(report)` tool.

### Database helpers

In `src-tauri/src/db.rs`, modeled on `create_quest_ref_internal` /
`list_quest_refs_internal`:

- `upsert_quest_report_internal(&self, payload: &WriteQuestReportPayload) -> Result<String, MonarchError>`
  — validates `quest_id` and `payload` non-empty, looks up the quest's
  `assignee_shadow_id` to populate `agent_id`, then `INSERT ... ON CONFLICT (quest_id) DO UPDATE SET payload = ?, agent_id = ?, updated_at = ?`.
  Returns the row id (existing id on conflict). Single function covers both
  first-write and revision paths because of `UNIQUE (quest_id)`.
- `get_quest_report_by_quest_internal(&self, quest_id: &str) -> Result<Option<QuestReportRow>, MonarchError>` —
  primary read shape. The detail panel in Slice C calls this. No
  list-by-quest needed because there's at most one.
- `list_quest_reports_for_agent_internal(&self, agent_id: &str) -> Result<Vec<QuestReportRow>, MonarchError>` —
  cross-quest list, ordered `created_at DESC`. Justifies the denormalized
  `agent_id` column.

`QuestReportRow` is a typed struct with Serde/Specta derives, mirroring
`QuestRefRow`. A `map_quest_report` helper for `rusqlite::Row -> QuestReportRow`.

### Tauri commands

Three new commands at the bottom of `db.rs`, alongside `db_create_quest_ref`:

- `db_save_quest_report(payload: WriteQuestReportPayload) -> Result<String, _>`
  — direct upsert via `upsert_quest_report_internal`, then
  `emit_quest_report_notification(quest_id, "saved", id)`. Mirrors
  `db_create_quest_ref` (captain-initiated Tauri writes bypass the
  persistence pipeline; only sidecar inbound events use PersistCommand).
  Slice B's sidecar tool will produce the same `WriteQuestReportPayload`
  shape but route it through `PersistCommand::WriteQuestReport` for write
  ordering against surrounding quest events.
- `db_get_quest_report(quest_id: String) -> Result<Option<QuestReportRow>, _>` —
  the only per-quest read shape, since there's at most one.
- `db_list_quest_reports_for_agent(agent_id: String) -> Result<Vec<QuestReportRow>, _>` —
  cross-quest list.

A new `emit_quest_report_notification` helper alongside `emit_quest_ref_notification`,
broadcasting on `quest-report-{quest_id}`.

### Tests

Inside the existing `#[tokio::test]` block at the bottom of `db.rs`,
following the `test_agent` helper pattern:

- Migration idempotency — run `init_schema` twice on the same in-memory DB, no
  error.
- Insert + fetch roundtrip — save a report, `get_quest_report_by_quest`
  returns the matching row.
- Upsert semantics — save a report, save again with the same `quest_id`
  and a different payload, `get_quest_report_by_quest` returns the new
  payload; `updated_at > created_at`; row count for the quest is 1.
- `agent_id` denormalization — saving a report looks up the quest's
  `assignee_shadow_id` and stores it; `list_quest_reports_for_agent`
  returns reports for that agent across multiple quests, ordered DESC.
- FK to `quest_nodes` — saving with a non-existent `quest_id` fails.
- Nullable FK to `memory_keeper_runs` — insert with
  `distilled_by_keeper_run_id = NULL` succeeds (the default path in
  Slice A); manually setting it to a real keeper-run id round-trips.
- Agent archive — when an agent is deleted, reports it authored keep
  the row but `agent_id` is `NULL` (verifies `ON DELETE SET NULL`).

## Resolved decisions

The four open questions from the original plan were answered in review:

1. **One report per quest**, enforced via `UNIQUE (quest_id)`. Slice B's
   sidecar tool uses upsert semantics — revisions replace, no draft
   accumulation. The roadmap calls it "the report" (singular); Keeper
   consumption in Slice D wants a singular thing; the rare quest-reopen
   case can be revisited if it becomes real.
2. **Tauri save bypasses the persistence pipeline.** Captain-initiated
   writes match the `db_create_quest_ref` / `db_record_quest_event`
   precedent; only sidecar inbound events route through `PersistCommand`.
3. **`agent_id` FK, not free-text `author`.** Denormalized from
   `quest_nodes.assignee_shadow_id` at write time, `ON DELETE SET NULL`
   for agent-archive symmetry. The report is fundamentally an artifact
   of the shadow that ran the quest; carrying the FK gives us cheap
   per-agent and (later) per-project queries.
4. **Full `CLAUDE.md` post-launch tables backfill** included in scope.
   Cheap, adjacent, and the kind of doc rot the recent docs-cleanup PR
   already addressed for a sibling area.

## Out of scope reminders

- **No sidecar tool, no executor prompt change** — Slice B.
- **No UI** — the captain cannot see a report after this slice lands.
  Slice C wires the renderer into the P5 quest detail panel.
- **No Keeper consumption** — the Keeper still reads only the raw event
  stream slice on quest-close ticks. Slice D wires `quest_reports.payload`
  in as a second input.
- **No quest-status transition wiring** — closing a quest doesn't fail if
  no report exists. The "report-on-close" contract is enforced by the
  executor's prompt + tool semantics in Slice B, not by the schema.
- **No P5 quest detail panel changes** — `QuestTimelineTool.svelte` is
  untouched in Slice A.
- **No completed migrations backfill** for the partial `CLAUDE.md` table
  list outside the `quest_reports` row (unless open question 4 lands as
  "yes, full backfill").
