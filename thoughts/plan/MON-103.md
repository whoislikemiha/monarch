# MON-103 — Quest-close Keeper trigger

Linear: [MON-103](https://linear.app/monarch-commander/issue/MON-103/p2-keeper-quest-close-trigger-deeper-distillation-pass)

## Goal

Give auto-created quests a real ending. When the captain marks a quest done, Monarch records the status transition, clears the agent's current quest pointer if it still points at that quest, and dispatches a Keeper run with `trigger='quest_close'` and quest provenance.

## Implementation plan

1. **Detect the transition in the quest update path**
   - Read the quest before and after `db_update_quest`.
   - Treat `previous.status != 'done' && next.status == 'done'` as the semantic close transition.
   - Record a `status_change` quest event for status changes.
   - Mirror the behavior through the WebSocket fallback command.

2. **Generalize Keeper dispatch**
   - Replace the continuous-only dispatch request with a small trigger enum.
   - Keep continuous compaction anchored to the last successful Keeper run.
   - Add quest-close dispatch anchored to `quest.started_at ?? quest.created_at`.
   - Insert `memory_keeper_runs.trigger='quest_close'` and populate `quest_id`.
   - Add `trigger` to the outbound `keeper_run` command so the sidecar can branch on model/prompt later.

3. **Preserve quest provenance at result time**
   - On `keeper_result`, load the `memory_keeper_runs` row by id.
   - Use the run's `quest_id` for memory `source_quest_id` and `compaction_tick` timeline event.
   - Fall back to `agents.current_quest_id` only for older / continuous runs without stored quest provenance.
   - Include `trigger` in the `compaction_tick` payload.

4. **Captain affordance**
   - Add a Mark done button to expanded non-done quests in `QuestTimelineTool`.
   - Send `status='done'` and a `completed_at` timestamp through `db_update_quest`.
   - Render compaction ticks as either continuous or quest-close ticks.

## Verification

- Create or auto-create a quest, expand it, click Mark done.
- Confirm status becomes `done`, `completed_at` is set, and a `status_change` event appears.
- With a Keeper model configured, confirm a `memory_keeper_runs` row has `trigger='quest_close'` and `quest_id`.
- Confirm the timeline receives a `compaction_tick` payload with `trigger='quest_close'`.
- Run `npm run build:sidecar`, `cargo check`, `npx svelte-check`, and `npm test`.

## Out of scope

- Separate cloud-tier model selection for quest-close.
- A distinct deeper-distillation prompt.
- First-person quest reports.
- Idle or abandonment compaction triggers.
- Rich manual quest editing beyond Mark done.
