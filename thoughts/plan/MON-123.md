# MON-123 — Decouple live-context compaction from memory distillation

> Research plan. Split the two jobs the MON-100 Keeper conflates: **Pi owns live-context compaction**, **the Keeper does memory only and rides Pi's compaction boundary**. See `thoughts/design/shadow-cognition/distillation.md` (§ "What changed (2026‑06)") and `roadmap.md` § P2c.

## Why

Measured on a real session (`agent-1780236218463-1`, the "make avatar toggle-able" task) against `~/Library/Application Support/monarch/monarch.db`:

- **Churn.** 5 Keeper runs in 17s on a trivial task. The trigger sums per-turn usage `input+output+cache_read+cache_write` (`sidecar/src/sidecar_protocol.rs` `MessageEnd`) into `tokens_since_last_compaction` and fires at `soft=25k / hard=30k` (`memory_config.rs`). `cache_read` ≈ the whole context re-read each turn, so one turn's usage ≈ the budget → fires ~every turn.
- **≈0 realized savings.** Full raw conversation = 47,189 tokens (tokenized with `o200k_base`); live context (reported `total_tokens` per assistant turn) climbed 11k→29k with **no drop** across all 5 compactions. `applyKeeperRewrite` preserves the recent tail and prose-summarizes the oldest, already-consumed messages, while the expensive recent file-reads stay raw. The "14→9 messages" UI counts messages, not tokens.
- **Substrate problem.** You cannot replace a tool's output with "agent read X" — the agent needs the file to keep working. Summarizing the working set is destructive; summarizing only the stale tail saves nothing.

## Key discovery — Pi already does this right (and it's already enabled)

`pi-coding-agent` (the local pi checkout, installed as `@mariozechner/pi-*` v0.73.1):

- `packages/agent/src/harness/compaction/compaction.ts`
  - `shouldCompact(contextTokens, contextWindow, settings)` → `contextTokens > contextWindow − reserveTokens`. **Level, not sum.**
  - `DEFAULT_COMPACTION_SETTINGS = { enabled: true, reserveTokens: 16384, keepRecentTokens: 20000 }`.
  - `findCutPoint` keeps ~20k recent tokens at clean turn boundaries; split-turn prefixes summarized separately.
  - `generateSummary` → structured checkpoint (Goal / Constraints / Progress / Decisions / Next Steps / Critical Context); iterative PRESERVE+merge with `UPDATE_SUMMARIZATION_PROMPT`.
- `packages/agent/src/harness/compaction/utils.ts` — `extractFileOpsFromMessage` + `formatFileOperations` append `<read-files>` / `<modified-files>` to the summary; carried across compactions. Re-read-on-demand.
- `packages/coding-agent/src/core/agent-session.ts`
  - `_runAutoCompaction("threshold" | "overflow")` runs in the loop after assistant messages (`agent-session.ts:~1867`).
  - Emits `compaction_start` / `compaction_end`.
  - Fires the `session_before_compact` extension hook with `{ preparation, branchEntries, customInstructions, signal }`; handler may `cancel` or supply a `compaction` result. `preparation.messagesToSummarize` is **the exact slice Pi is about to evict**.

Pi's auto-compaction is on for Monarch (`createAgentSession` in `runtime-manager.ts:377` passes no settings → defaults), but never runs because our Keeper preempts it at 25–30k (Pi fires ~`128000 − 16384 ≈ 112k`).

## Current Monarch wiring (what we change)

  - `keeperRun(cmd)` (~787): captures `tailAnchor`, runs `runKeeper`, emits `keeper_result` (claims + summary), stashes `pendingKeeperRewrite`.
  - `applyKeeperRewrite(managed, rewrite)` (~843): sets `session.agent.state.messages = [summaryMsg, ackMsg, ...tail]`, emits `keeper_rewrite_applied`.
  - `turn_end` listener (~506) drains `pendingKeeperRewrite`.
  - `compact(agentId)` (~763) calls `session.compact()` (Pi native) — manual path only.
- `src-tauri/src/agent/event_handler.rs`
  - `maybe_trigger_keeper` (~519): soft at `TurnEnd`, hard at assistant `MessageEnd`; compares `tokens_since_last_compaction` to thresholds; dispatches `KeeperRun`.
  - `KeeperRewriteApplied` handler (~349) → "✦ Context compacted (… N → M messages …)" notice.
  - `handle_keeper_result` (~763 in manager-adjacent) → persists memories + "◈ Keeper distilled N …" notice; resets counter.
- `src-tauri/src/sidecar_protocol.rs` — `MessageEnd` accumulates `tokens_since_last_compaction` (~1035).

## Slices

### Slice A — Stop the rewrite; let Pi own live context
1. **Sidecar:** delete `pendingKeeperRewrite` field, `applyKeeperRewrite`, and the `turn_end` drain. `keeperRun` still emits `keeper_result` (claims only). Stop emitting `keeper_rewrite_applied`.
2. **Sidecar protocol / Rust:** remove the `KeeperRewriteApplied` event + its "Context compacted" notice (or keep the variant inert if other code references it — prefer removal + `cargo run -- --export-bindings`).
3. **Sidecar → Rust:** forward Pi's `compaction_start` / `compaction_end` as new sidecar events so Rust can emit an honest "context compacted by Pi" status (real `tokensBefore` from `CompactionResult`). Wire through `sidecar_protocol.rs` + `event_handler.rs`.
4. Keep the per-turn memory trigger **for now** (memory still forms) — Slice B replaces it. Net effect of A: Monarch stops mutating `state.messages` behind Pi; Pi's compaction can engage cleanly on long sessions.
5. **Verify:** `npm run build:sidecar`, `cargo check` (from `src-tauri/`), `cargo run -- --export-bindings`, `npx svelte-check`. Manual: long session no longer shows the synthetic "Keeper compaction" scaffold; Pi compaction fires near the window.

### Slice B — Keeper rides the compaction boundary (memory only)
1. **Sidecar:** register a `session_before_compact` handler (via the same extension path as `bindExtensions` / the runner). On the hook, dispatch a Keeper memory run over `preparation.messagesToSummarize` (no rewrite, no cancel — return `undefined` so Pi proceeds). Emit `keeper_result` (claims only).
2. **Rust:** remove `maybe_trigger_keeper`'s per-turn dispatch + the `tokens_since_last_compaction` accumulator (`sidecar_protocol.rs`); drop `DEFAULT_SOFT/HARD_THRESHOLD_TOKENS` and the `memory.toml` threshold fields (or mark deprecated). Keep `KeeperRunTrigger::QuestClose`. Add `KeeperRunTrigger::CompactionBoundary` (slice provided by the hook, not re-derived from `since`).
3. `dispatch_keeper_run` / `render_keeper_slice` adapt: the slice now comes from the hook payload rather than `list_agent_messages_since`. Keep PRIOR SUMMARY / RELATED MEMORIES sections.
4. **Verify:** same build/type gates. Manual: trivial task → 0–1 Keeper runs (not 5); claims distilled from a coherent slice.

### Slice C — UI + observability
1. Compaction timeline rows show real token before→after (from Pi `CompactionResult.tokensBefore` + post estimate), not message counts.
2. Reconcile `compaction_tick` quest-event semantics with Pi-driven compaction.
3. Remove dead config UI in `MemorySettings.svelte` for soft/hard thresholds; keep the Keeper model config.

## Risks / open questions

- **Extension hook registration.** Confirm Monarch can register a `session_before_compact` lifecycle handler through its existing extension binding (it currently passes `customTools` + `bindExtensions({uiContext, commandContextActions})`). If the runner only exposes tool hooks, Slice B needs a small Pi-side affordance or a different observation point (`compaction_end` after the fact, distilling from the persisted evicted entries).
- **Direct `state.messages` mutation elsewhere.** `loadSession` / restore paths also set `state.messages` (`runtime-manager.ts:~962`). Leave those; only the Keeper rewrite is removed.
- **Quest-close trigger** must keep working unchanged through both slices.
- **Verification is run-the-app.** Compile gates catch type breakage; behavior (no churn, real savings, memory quality) needs a live session + a DB re-measure with the `/tmp/keeper_tokens.py` method.
