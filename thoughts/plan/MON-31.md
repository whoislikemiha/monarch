# MON-31 — Introduce `MonarchError` domain error type

Linear: https://linear.app/monarch-commander/issue/MON-31
Branch: `mon-31-introduce-monarcherror-domain-error-type`
Base: `mon-14-phase-1-rust-state-ownership` (Wave 2 rule — not `master`)

## Summary

Every `#[tauri::command]` in `src-tauri/src/` currently returns `Result<T, String>`, built by stringly `.map_err(|e| e.to_string())` at every DB / sidecar / IO call site. The frontend receives an opaque string with no way to branch on *what* failed. This plan introduces a `thiserror`-based `MonarchError` with a small, hand-picked set of variants, a stable serialized DTO shape (`{ kind, message, details }`) that passes through specta as a typed error, and migrates the whole Tauri command boundary to `Result<T, MonarchError>`. The frontend gains at least one `match`-on-`kind` call site (spawn failure in `App.svelte`). Wave 2 step 1 of five — this unblocks MON-32 / MON-35 / MON-33 by giving them a stable command-signature shape to refactor *around* instead of rewriting errors three more times.

Also the `PersistCommand::apply` / `run_persist_consumer` paths added by MON-37 — **these are internal to the persistence consumer, not command returns, so they are out of scope** per the Wave 2 handoff note.

- `src-tauri/src/models.rs` — `get_models`, `get_provider_auth_status`, and the inner `fetch_*` HTTP fetchers. `reqwest::Error` needs a source variant (`Http`? or fold into `Sidecar` as a generic external-call variant? — see open questions).
- `src-tauri/src/toolbox/placeholder.rs` — `toolbox_placeholder_ping` (trivial, one line).
- `src-tauri/src/ws.rs` — `dispatch_command`, `make_response`, `str_field`. This is MON-33's territory but it also currently returns `Result<Value, String>` and *consumes* every `ws_*` function. Plan below.
- `src-tauri/src/lib.rs` — `export_bindings()` itself returns `Result<(), String>`; since it's not a Tauri command, it can stay (or migrate as a consistency win).

### Rust — new file

- `src-tauri/src/error.rs` — new module. Holds the `MonarchError` enum, the DTO serializer, the `Result<T>` alias, and `From` impls for the common source types (`rusqlite::Error`, `std::io::Error`, `serde_json::Error`, `reqwest::Error`, `tauri::Error`, and the poisoned-lock errors from `std::sync::PoisonError`).

### Rust — dependency additions

- `src-tauri/Cargo.toml` — `thiserror = "1"` (new). `thiserror` is not currently in the dependency list. No other dep changes required; `specta` is already pulled in and will handle the DTO's `Type` derivation.

### Frontend — consumers

- `src/lib/AgentView.svelte` — has ~15 `try`/`catch` sites but is not required to migrate; MON-31's bullet only requires *one* call site demonstrating kind matching. Leave the rest for consumers to adopt incrementally.
- `src/lib/api.ts` — the `invoke` shim that specta rewrites bindings through. Unlikely to need changes: Tauri's `invoke` rejection carries whatever shape the Rust `Serialize` impl emits, so once `MonarchError` serializes to `{ kind, message, details }`, the caller sees that object directly. Worth re-reading to confirm.

## What needs to change

### 1. New `error` module

Create `src-tauri/src/error.rs` containing:

- A `MonarchError` enum with variants: `Sidecar(SidecarErrorKind)`, `Db`, `Persistence`, `Http`, `InvalidInput`, `NotFound`, `Lock`, `Io`, `Serde`. Each wrapped variant carries a `#[source]` where there's a meaningful source chain (`Db(rusqlite::Error)`, `Io(std::io::Error)`, `Serde(serde_json::Error)`, `Http(reqwest::Error)`). `InvalidInput` and `NotFound` take a plain message (no source). `Lock` takes a description of what was locked (`&'static str`) so the frontend can tell "agents map" apart from "app-handle slot".
- `SidecarErrorKind` inner enum: `ProcessDown`, `StdinWrite`, `ReplyError { message: String }`, `Parse { raw: String }`. The outer `Sidecar` variant wraps this; the serializer **flattens** the sub-kind into the top-level DTO `kind` field as `"sidecarProcessDown" | "sidecarStdinWrite" | "sidecarReplyError" | "sidecarParse"` so the frontend can type-narrow without a nested match. Added for observability (see resolved decision #2).
- `pub type Result<T> = std::result::Result<T, MonarchError>;` in `error.rs`, re-exported from `lib.rs` so call sites use `use crate::Result;` (standard Rust crate convention — see resolved decision #6).
- `impl Serialize for MonarchError` that projects to the DTO `ErrorDto { kind: &'static str, message: String, details: Option<String> }`. `kind` is a stable camelCase string (`"sidecar…"`, `"db"`, `"http"`, `"invalidInput"`, …) and is the ONLY stable contract for the frontend. `message` is `Display::fmt` output. `details` is `Some(source.to_string())` when a `#[source]` chain exists; for `Sidecar(ReplyError/Parse)` it carries the sub-kind's payload (`message` / `raw`); otherwise `None`.
- `ErrorDto` itself must derive `specta::Type` so the typed error surfaces in `bindings.ts` as a real TS type that the frontend can type-narrow on.
- `From` impls for each wrapped source (`From<rusqlite::Error> → Db`, `From<std::io::Error> → Io`, `From<serde_json::Error> → Serde`, `From<reqwest::Error> → Http`, `From<tauri::Error> → …`) so `?` just works at the call sites. The `rusqlite` conversion is a dumb blanket → `Db`; call sites that want `QueryReturnedNoRows` to become `NotFound` use `.optional()?.ok_or_else(|| MonarchError::not_found(...))` (resolved decision #5). **No** generic `From<String>` or `From<&str>` — those would defeat the whole point by re-enabling stringly-typed error propagation.
- Helper constructors: `MonarchError::not_found(what: impl Into<String>)`, `::invalid_input(…)`, `::lock(what: &'static str)`. These replace the common ad-hoc `format!(...)` patterns at call sites with structured calls.
- A `PoisonError<T>` → `MonarchError::Lock` conversion helper. Because `PoisonError` is generic, a blanket `From` impl needs care; the pragmatic pattern is a helper `fn lock_poisoned(what: &'static str) -> impl FnOnce(PoisonError<T>) -> MonarchError` that call sites use as `.lock().map_err(lock_poisoned("agents"))?`. That also gives each site a recognisable label in the DTO.

Register the module in `src-tauri/src/lib.rs` as `mod error;` near the top.

### 2. Command migration

Replace the return type on every `#[tauri::command]` function across `agent.rs`, `db.rs`, `persistence.rs`, `models.rs`, `toolbox/placeholder.rs` with `Result<T, MonarchError>` (via the alias where possible). Delete the `.map_err(|e| e.to_string())` call sites — most will become a bare `?` because of the `From` impls in the error module. Ad-hoc `format!("not found: {id}")` string errors become `MonarchError::not_found(format!("session {id}"))`.

Internal helpers (e.g. `Database::save_message_internal`, `write_command`, `get_app_handle`, `ensure_sidecar`) also migrate to `Result<T, MonarchError>`. This is not required by the acceptance bullet ("zero `Result<T, String>` on commands") but leaving them as `Result<_, String>` would force a `.map_err(|e| MonarchError::...(e))` band-aid at every command, which defeats the purpose. Migrate helpers too.

Explicit **exceptions** that stay `Result<_, String>` (or `Result<_, MonarchError>` as a consistency win, pick one in the plan review):

- `PersistCommand::apply` and `run_persist_consumer` in `agent.rs` — internal to MON-37's consumer loop; handoff note calls these out as out of scope.
- `ws::dispatch_command` and `ws::make_response` — see section 4.
- `lib::export_bindings` — not a Tauri command, not user-facing; migrate for consistency, low risk.

### 3. `spawn_agent` handling

`spawn_agent` has 13 args and is deliberately excluded from the specta `collect_commands!` call (`lib.rs:37`) because specta caps at 10. MON-35 will fix this. For MON-31:

- `spawn_agent` and `ws_spawn_agent` still migrate to `Result<T, MonarchError>` — consistency with the rest of the surface.
- They still won't appear in the specta builder; MON-35's job to re-add them.
- **Do not** collapse the arg list into a struct in this PR. MON-35's whole scope is that collapse; pre-doing it here would step on MON-35's diff.
- **Do not** touch the `too_many_arguments` clippy warnings. MON-35 fixes them by eliminating the root cause.

### 4. WS boundary (`ws.rs`)

The WebSocket dispatcher is MON-33's unification target, but MON-31 has to pick a policy. Recommended shape:

- `ws_*` wrapper functions in `agent.rs` / `db.rs` / `persistence.rs` / `models.rs` migrate to `Result<T, MonarchError>` alongside their `#[tauri::command]` counterparts. They already look identical to the commands; keeping them in sync is critical.
- `ws::dispatch_command` migrates to `Result<Value, MonarchError>`. `ws::make_response` **embeds the `ErrorDto`** as the JSON-RPC `error.data` field rather than flattening to a string (resolved decision #4). This gives WS clients the same typed shape Tauri clients see and means MON-33 starts from a consistent error surface. Runtime cost is identical to the flatten path.
- `str_field` and other small WS helpers also migrate to `MonarchError` — `InvalidInput` for missing/bad fields is the natural mapping.

### 5. Specta / bindings

Regenerate `src/lib/bindings.ts` via `cargo run -- --export-bindings` as part of the final commit. The `ErrorDto` type should surface as a named type export. Every command's `typedError<T, E>` wrapper now has the DTO type in the `E` position instead of `string`.

**Verify**: the bindings export still builds after the error-type change. `export_bindings` itself returns `Result<(), String>`; if we migrate it to `MonarchError`, the `.map_err(...)` calls in its body need updating. Low-risk; isolated to that function.

### 6. Frontend acceptance site

In `src/App.svelte` around line 305 (`spawn_agent` `.catch`), replace `String(err)` with a small helper that:

- Inspects `err?.kind` (guarded — `err` can be anything when Tauri marshalling fails).
- Builds a user-facing string per kind: `sidecar` → "Sidecar unreachable", `db` → "Database error: " + `err.message`, `invalidInput` → `err.message` verbatim, default → `String(err)` (the current behavior).
- Pushes the string onto `stderrLines` the same way the current code does.

This satisfies the "frontend can `match` on `error.kind` in at least one call site" acceptance bullet without adding any new UI.

### 7. Verification

- `cargo check` and `cargo clippy` (`--all-targets` if feasible) must pass with no new warnings. The 2 pre-existing `too_many_arguments` warnings on `spawn_agent` / `ws_spawn_agent` are expected to remain (MON-35 fixes them); MON-31's PR note should mention this so review doesn't flag it.
- `svelte-check` must pass.
- `cargo run -- --export-bindings` regenerates `src/lib/bindings.ts` cleanly.
- Manual smoke: start the app, trigger a spawn with an invalid provider and confirm the `stderrLines` message reflects kind-based text rather than the raw serialized DTO.
- No Rust test harness exists on Windows (parking-lot finding from MON-30). Verification is manual.

## Resolved decisions

All six open questions were settled during plan review. Recording here so future me doesn't re-litigate:

1. **`Http` variant — added.** `reqwest::Error` from `models.rs` maps to a dedicated `MonarchError::Http { source: reqwest::Error }`. Do not fold into `Sidecar` (wrong semantically) or hide under `External` (too vague).

2. **`Sidecar` sub-kinds — add them.** Reason: we're moving fast and need granular tracing/observability on the sidecar interaction, which is the highest-churn surface. Rust side gets `Sidecar(SidecarErrorKind)` where `SidecarErrorKind` is `ProcessDown | StdinWrite | ReplyError { message: String } | Parse { raw: String }`. The DTO **flattens** sub-kinds into the top-level `kind` field so the frontend can type-narrow directly: `kind: "sidecarProcessDown" | "sidecarStdinWrite" | "sidecarReplyError" | "sidecarParse"`. The `message` / `details` fields carry the per-variant payload (reply text, raw parse input). This grows the stable contract by 4 kinds on day one — accepted cost for observability.

3. **Helper migration — yes.** `Database::*_internal`, `write_command`, `get_app_handle`, `ensure_sidecar`, `send_to_sidecar`, and the rest of the internal helpers migrate to `Result<T, MonarchError>` alongside the commands. Strict scope widening vs the acceptance bullet, but leaving helpers on `Result<_, String>` would force a `.map_err(MonarchError::from_string)` band-aid at every command and defeat the point.

4. **WS boundary — embed the DTO.** `ws::make_response` serializes `MonarchError` via its `Serialize` impl into the JSON-RPC response's `error.data` field, not a flattened `.to_string()`. Runtime cost is identical; WS clients get the same typed shape as Tauri clients; MON-33's unification starts from a consistent surface instead of re-unifying it. `dispatch_command` migrates to `Result<Value, MonarchError>`.

5. **`From<rusqlite::Error>` — blanket to `Db`.** Every `?` in DB code just works. Sites that want "missing row = `NotFound`" use rusqlite's idiomatic `.optional()?.ok_or_else(|| MonarchError::not_found(...))` — `.optional()` turns `QueryReturnedNoRows` into `Ok(None)` and the caller decides. Do **not** add a smart `From` that inspects variants (steals the decision from the caller: missing-row-is-user-error vs missing-row-is-corruption depends on context, not on the error variant).

6. **`Result<T>` alias — standard Rust practice.** `pub type Result<T> = std::result::Result<T, MonarchError>;` in `error.rs`, re-exported from `lib.rs` so call sites write `use crate::Result;` and then `fn foo() -> Result<Foo>`. This is what `std::io::Result`, `anyhow::Result`, `reqwest::Result`, `serde_json::Result`, and `sqlx::Result` all do. The "shadows `std::result::Result`" concern is overblown — near-zero functions in this crate return non-`MonarchError` errors.

## Out of scope reminders

- **MON-37's internal `Result<(), String>`** on `PersistCommand::apply` and `run_persist_consumer`. Not Tauri command returns. Leave alone (or migrate as a pure consistency win, but do not conflate with the acceptance bullet).
- **`eprintln!` → `tracing` migration** in `agent.rs`. Parking-lot item, file-wide sweep, not a MON-31 carve-out.
- **`std::sync::Mutex` / `tokio::sync::RwLock` unification.** MON-34's job. MON-31 only carves out the `MonarchError::Lock` variant; lock topology stays untouched.
- **`too_many_arguments` clippy warnings** on `spawn_agent` / `ws_spawn_agent`. MON-35's job via `SpawnAgentRequest` struct. Do not collapse the signature here.
- **Frontend error-handling coverage beyond one site.** The acceptance is "at least one call site"; the spawn-failure handler in `App.svelte` is the target. `AgentView.svelte`'s 15+ `try`/`catch` sites are out of scope — consumers adopt the DTO incrementally in later PRs.
- **WS error shape final design.** MON-33 owns the WS unification. MON-31 picks the minimum-viable flatten-at-boundary policy and moves on.
- **Rust test harness / CI setup.** Parking-lot item. Verification remains manual per Wave 1 convention.
- **New UI for error display.** No toast component, no error view. The acceptance bullet is satisfied by a kind-aware message string pushed into the existing `stderrLines` array.
