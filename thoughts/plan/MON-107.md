# MON-107 — P4 Slice A: nested quest events + L2 substrate

Linear: [MON-107](https://linear.app/monarch-commander/issue/MON-107/p4-slice-a-nested-quest-events-and-l2-working-memory-substrate)

## Goal

Lay the Rust/SQLite substrate for P4 executor narration. After this slice, the backend can store nested action-level quest events, maintain L2 working memory v0, and mirror tool execution start/end into the active action. No sidecar narration tools or frontend action renderer are required yet.

## Current state

- `quest_events` is flat: `id`, `quest_id`, `event_type`, `actor`, `payload_json`, `created_at`.
- `RecordQuestEventPayload` inserts only new rows; there is no update path.
- The persist pipeline already serializes sidecar events through one consumer and can write quest events for `memory_suggestion` / Keeper ticks.
- `agents.current_quest_id` is populated by MON-105 and cleared on quest close by MON-103.
- Tool results are persisted as `messages.role='toolResult'`, but tool start/end are not mirrored into `quest_events`.
- There is no structured L2 store.

## Data model

1. Extend `quest_events` idempotently:
   - `parent_event_id TEXT REFERENCES quest_events(id) ON DELETE CASCADE`
   - `author TEXT`
   - `surface_override TEXT`
   - `payload_schema_version INTEGER NOT NULL DEFAULT 1`
   - index `idx_quest_events_parent(parent_event_id)`

2. Add `agent_working_memory`:
   - `agent_id TEXT PRIMARY KEY REFERENCES agents(id) ON DELETE CASCADE`
   - `payload_json TEXT NOT NULL`
   - `updated_at TEXT NOT NULL`

3. Extend Rust DTOs:
   - `QuestEventRow` includes the new columns.
   - `RecordQuestEventPayload` accepts optional `parent_event_id`, `author`, `surface_override`, and `payload_schema_version`.
   - Add an internal update helper for quest event payload mutations by id.

## L2 v0 shape

```json
{
  "schema_version": 1,
  "current_quest_id": "quest-id-or-null",
  "current_quest_path": ["Root quest", "Subquest"],
  "current_action": {
    "event_id": "quest-event-id",
    "quest_id": "quest-id",
    "intent": "Understand the failing authentication test",
    "started_at": "2026-04-29T..."
  },
  "recent_actions": [
    {
      "event_id": "quest-event-id",
      "quest_id": "quest-id",
      "intent": "Run the focused verification",
      "outcome": "The focused auth test now passes.",
      "completed_at": "2026-04-29T...",
      "auto_closed": false
    }
  ],
  "updated_at": "2026-04-29T..."
}
```

Keep L2 compact: no file contents, no tool-result blobs, no execution plan. It is an index into the quest event log.

## Persistence flow

1. **Action transition**
   - Input: `agent_id`, `quest_id`, `intent`, optional `previous_outcome`.
   - If an L2 current action exists:
     - close the parent `coherent_action` by updating its payload (`status`, `completed_at`, `outcome`, `auto_closed` when needed).
     - insert `executor_action_outcome` child.
     - append to `recent_actions`.
   - Insert a new `coherent_action` with `status='active'`.
   - Set L2 `current_action` to that event.

2. **Action complete**
   - Close the current action explicitly.
   - Insert `executor_action_outcome` child.
   - Clear L2 `current_action`, append to `recent_actions`.

3. **Auto-close**
   - When a new transition arrives without `previous_outcome`, close prior action with `auto_closed=true`, `auto_closed_reason='new_action_started'`, and a fallback outcome.
   - Later slices can call the same helper for `agent_end` / abort boundaries.

4. **Executor decision**
   - Insert `executor_decision` under current action when one exists; otherwise top-level under the current quest.

5. **Tool calls**
   - On `ToolExecutionStart`, insert one `tool_call` child under the current action with `status='running'`, `args_preview`, and `started_at`.
   - On `ToolExecutionEnd`, update that same event payload with `status`, `result_preview`, `is_error`, `duration_ms`, and `completed_at`.
   - Skip P4 narration tool names when they exist in MON-108 (`set_current_action`, `complete_action`, `record_decision`).

6. **Missing quest repair**
   - If a P4 narration event arrives with no `current_quest_id`, auto-create a root quest using the action intent as title, assign it to the agent, set `agents.current_quest_id`, then continue.
   - If auto-create fails, log and drop quest-event writes rather than corrupting L2.

7. **L2 rebuild fallback**
   - Internal helper reconstructs v0 from quest events when the row is missing/invalid:
     - active `coherent_action` with `status='active'` becomes `current_action`.
     - last 10 completed/auto-closed coherent actions become `recent_actions`.
   - No public command/UI in this slice.

## Code areas

- `src-tauri/src/db.rs`
  - migrations
  - DTO updates
  - quest event insert/update helpers
  - working-memory get/upsert/rebuild helpers

- `src-tauri/src/sidecar_protocol.rs`
  - add P4 inner-event variants only if needed for compile-time matching in this slice (`ActionTransition`, `ActionComplete`, `ExecutorDecision`).
  - `apply_event` remains `NoOp` for P4 semantic events; live-state exposure comes after DB/L2 helpers are stable.

- `src-tauri/src/agent/event_handler.rs`
  - resolve current quest for P4 semantic/tool events.
  - pass enough context into `build_persist_commands`.

- `src-tauri/src/agent/persist.rs`
  - add persistence commands for action transition/complete/decision and tool-call mirror.
  - apply each logical transition atomically inside the consumer.

## Tests

Add focused Rust tests where the existing module structure makes them cheapest:

- migration/DTO compatibility: pre-P4 rows still map with `None` new fields.
- action transition creates a `coherent_action` and sets L2 `current_action`.
- transition with `previous_outcome` closes prior action and appends `recent_actions`.
- transition without `previous_outcome` auto-closes prior action.
- `action_complete` clears `current_action`.
- tool start/end creates then updates one `tool_call` child event.
- L2 rebuild derives current/recent actions from quest events.
