# MON-98 — P1: Captain identity, end-to-end

## Summary

P1 establishes the L1 identity substrate: a singleton `captain` record and per-shadow identity rows, each versioned with a full-snapshot, `supersedes_id`-chained history. The system prompt builder (`shadow-oath.ts`) gains two new injection sites — L1a captain and L1b shadow — slotted in before the existing behavior section. A new Identity toolbox tool gives the captain in-app editing over both layers. Every shadow picks up identity changes on the next turn without any agent restart; rollback is a pointer flip, no data destruction.

This is entirely additive. Nothing in the existing agent lifecycle changes; the only new runtime dependency is that `buildSystemPrompt` receives captain and shadow identity payloads from Rust (via the sidecar command protocol) and injects them into the assembled prompt string.

## Relevant files and areas

### Rust — schema and persistence

- **`src-tauri/src/db.rs`** — `init_schema` function (around line 128) is where all `CREATE TABLE IF NOT EXISTS` statements live, followed by idempotent `ALTER TABLE` migration blocks at the end. Three new tables go here: `captain`, `captain_identity_versions`, `shadow_identity_versions`. One new `ALTER TABLE agents ADD COLUMN identity_version_id` migration block goes in the trailing migration section. The existing pattern for migrations is `let _ = conn.execute_batch(...)` — "ignore already-exists" semantics, idempotent.

- **`src-tauri/src/agent/commands.rs`** — Tauri command definitions. New commands needed: `get_captain_identity`, `update_captain_identity`, `get_shadow_identity`, `update_shadow_identity`. Each follows the existing three-tier signature: `AppHandle + State<AgentManager> + State<Database> + request struct`. Request structs use `#[serde(rename_all = "camelCase")]` and derive `specta::Type`. Stay under the 10-arg Specta limit by grouping fields into a request struct.

- **`src-tauri/src/agent/manager.rs`** — `AgentManager` and `LiveAgentState`. Shadow identity version ID may need to be part of `LiveAgentState` (or retrieved on demand). Assess at implementation time whether `identity_version_id` needs to live in the in-memory manager snapshot or is always fetched from DB on session start.

- **`src-tauri/src/lib.rs`** — registers Tauri commands via `tauri::generate_handler![]`. New identity commands must be added here and to `src-tauri/src/ws.rs` (WebSocket dispatch for browser-mode fallback).

### Sidecar — system prompt

- **`sidecar/src/shadow-oath.ts`** — `buildSystemPrompt(shadow, cwd, projectInstructions?)` (lines 69–114) assembles the prompt. Currently: header → grade description → permissions → personality directive → behavior → tools → work guidelines → metadata. Two new sections slot in after the header block (grade/permissions/personality) and before the behavior section:
  - `## Captain` — captain identity payload (L1a)
  - `## Shadow identity notes` — shadow identity payload (L1b, in addition to the existing name/title/grade)
  The function signature will need to accept the two new optional string parameters (captain payload, shadow payload).

- **`sidecar/src/protocol.ts`** — defines the command types sent from Rust to the sidecar. The `create_session` command already carries `projectInstructions`. Captain and shadow identity payloads need to be added here as optional fields on `CreateSessionCommand` (or equivalent). This is the wire protocol change — keep payloads as pre-rendered strings (Rust renders them from the DB rows before serialising).

- **`sidecar/src/runtime-manager.ts`** — calls `buildSystemPrompt` when creating a Pi session. Will need to thread the two new payload fields through from the incoming command to the prompt builder.

### Frontend — toolbox tool

- **`src/lib/toolbox/tools/`** — new `IdentityTool.svelte` component. Follows the pattern of `ShadowStatsTool.svelte` (agentContext access, invoke for backend calls, $state for loading/error/data). Two sections: **Captain** (shared across agents — reads/writes captain identity; the captain panel is the same regardless of which agent is open) and **Shadow** (per-agent — reads/writes shadow identity for `agentContext.agentId`).

- **`src/lib/toolbox/registry.ts`** — register `IdentityTool` with a stable `id`, `title`, icon SVG, and `order: 5` (before the context inspector at order 10).

- **`src/lib/bindings.ts`** — auto-generated by tauri-specta. Do not edit. Regenerate with `cargo run -- --export-bindings` from `src-tauri/` after adding the new Tauri commands.

### Design reference

- **`thoughts/design/shadow-cognition/substrate.md`** — defines L1a captain (lines 30–44), L1b shadow (lines 46–56), versioning model (lines 92–94), and the prompt loading order (lines 259–272). ## What needs to change

### 1. Schema (db.rs)

Three new tables added in `init_schema`:

- **`captain`** — singleton enforced via `CHECK (id = 1)`. Columns: `id INTEGER PRIMARY KEY`, `name TEXT NOT NULL`, `current_version INTEGER NOT NULL REFERENCES captain_identity_versions(id)`. The `current_version` FK creates a circular dependency with `captain_identity_versions` at creation time; resolve by creating `captain_identity_versions` first, inserting a seed row, then inserting the `captain` row in the app-startup "upsert captain if missing" logic.

- **`captain_identity_versions`** — row-per-version. Columns: `id INTEGER PRIMARY KEY`, `captain_id INTEGER NOT NULL REFERENCES captain(id)`, `payload TEXT NOT NULL` (free-text, markdown-friendly), `created_at TEXT NOT NULL`, `supersedes_id INTEGER REFERENCES captain_identity_versions(id)`, `edit_note TEXT`. Index on `(captain_id, created_at)`.

- **`shadow_identity_versions`** — same shape scoped to agents. Columns: `id INTEGER PRIMARY KEY`, `agent_id TEXT NOT NULL REFERENCES agents(id)`, `payload TEXT NOT NULL`, `created_at TEXT NOT NULL`, `supersedes_id INTEGER REFERENCES shadow_identity_versions(id)`, `edit_note TEXT`. Index on `(agent_id, created_at)`.

One migration block at the end of `init_schema`:
- `ALTER TABLE agents ADD COLUMN identity_version_id INTEGER REFERENCES shadow_identity_versions(id)`.

Startup: after `init_schema`, check if `captain` row with `id=1` exists; if not, insert a seed `captain_identity_versions` row (empty payload) and then `captain` row pointing to it. This guarantees the singleton exists from first launch.

### 2. Rust persistence commands

New DB functions (following the `db_*` naming convention):
- `db_get_captain_identity` — returns the current captain version row (payload + metadata).
- `db_upsert_captain_identity(payload, edit_note)` — inserts a new `captain_identity_versions` row, flips `captain.current_version`.
- `db_get_shadow_identity(agent_id)` — returns the current shadow version row for the agent, or `None` if `identity_version_id` is null.
- `db_upsert_shadow_identity(agent_id, payload, edit_note)` — inserts a new `shadow_identity_versions` row, updates `agents.identity_version_id`.

These are called by Tauri commands in `commands.rs` and registered in `lib.rs` + `ws.rs`.

### 3. Sidecar protocol and session creation

`CreateSessionCommand` in `protocol.ts` gains two optional string fields: `captainIdentityPayload` and `shadowIdentityPayload`. Rust populates these by reading the current captain and shadow identity from DB before sending the `create_session` command to the sidecar.

In `runtime-manager.ts`, thread these through to `buildSystemPrompt`.

In `shadow-oath.ts`, `buildSystemPrompt` accepts the two new optional parameters and conditionally injects a `## Captain` block and a `## Shadow` block into the prompt string.

### 4. Identity toolbox tool

`IdentityTool.svelte` — two-panel layout:

- **Captain panel**: text area bound to captain identity payload; "Save" calls `update_captain_identity`. No `agentContext` dependency — captain is global. Show current version metadata (created_at, edit_note).
- **Shadow panel**: text area bound to shadow identity payload for the current agent; "Save" calls `update_shadow_identity`. Disabled/empty state when `agentContext` is null. Show current version metadata.

Both panels should reflect unsaved state (dirty tracking) and handle loading/error states.

Register in `registry.ts` at `order: 5`.

### 5. Binding regeneration

After all Rust commands are registered, run `cargo run -- --export-bindings` from `src-tauri/` to regenerate `src/lib/bindings.ts`. Commit the generated file as part of the same PR.

## Decisions (open questions resolved)

1. **Prompt slot** — captain identity renders *after* the grade/permissions/personality block, before the behavior section. Order in `buildSystemPrompt`: header → grade/permissions/personality → `## Captain` (L1a) → `## Shadow` (L1b payload) → behavior → tools → guidelines → metadata.

2. **Payload shape** — pure markdown blob + `captain.name` column only. No structured fields beyond name in P1.

3. **Shadow identity seed** — empty payload on agent creation. Existing hardcoded grade/personality sections in `shadow-oath.ts` remain untouched; the L1b block appends additional captain-authored context on top of them.

4. **Auto-memory migration** — deferred entirely. Both auto-memory and L1 coexist; no migration tooling in P1.

5. **Token budget** — soft enforcement: the Identity tool UI shows a live token counter (estimate via character heuristic: chars ÷ 4). Display a warning indicator when approaching the 3000-token combined cap. No server-side truncation.
