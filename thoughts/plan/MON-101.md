# MON-101 — P2 Slice C: retrieval read path

Linear: [MON-101](https://linear.app/monarch-commander/issue/MON-101/p2-slice-c-retrieval-read-path-memories-surface-on-user-turn)

## Goal

Complete the first memory loop: memories formed by MON-99 / MON-100 are retrieved on a related future user turn and injected into the executor's prompt as `## Relevant Memories`.

## Current substrate

- `memories`, `memories_fts`, `memory_keeper_runs`, `MemoryIndex`, and Memory Inspector v0 exist from MON-99.
- MON-100 writes Keeper claims and rebuilds HNSW after successful Keeper runs.
- `memory_config.rs` already has `top_k` on `MemoryConfig` / `ResolvedMemoryConfig` with a default of 5.
- The sidecar has no generic synchronous Rust invoke path; it emits JSONL events and receives JSONL commands.

## Implementation plan

1. **Rust hybrid search command**
   - Add a `MemorySearchResult` DTO carrying the `MemoryRow`, source (`fts`, `vector`, `hybrid`), and simple score metadata.
   - Add `memory_search_for_agent(agent_id, query, top_k?)`.
   - No-op on empty query or uninitialized embedder/vector index.
   - Run FTS5 top-K and HNSW top-K, dedupe by memory id, preserve a deterministic merged order: hybrid hits first, then FTS order, then vector order.
   - Fetch rows through `get_memory_internal` so archived rows stay excluded by search inputs; defensively skip missing/archived rows.

2. **Access tracking**
   - Add a DB helper to bump `access_count` and `last_accessed_at` for retrieved memory ids.
   - Call it from the search command after final ordering.
   - This write is small and local to the command; it does not need the sidecar persistence queue because retrieval is a Rust command path, not an event-handler write.

3. **Sidecar request/response**
   - Add sidecar event `memory_search_request { agentId, requestId, query, topK? }`.
   - Add Rust command `memory_search_response { agentId, requestId, results }`.
   - Runtime manager keeps a per-agent resolver map with a short timeout. If Rust does not answer quickly, retrieval is skipped and the user turn proceeds.
   - Rust handles the request in `event_handler.rs`, calls `memory_search_for_agent` internals, then sends `MemorySearchResponse` to the sidecar.

4. **Prompt injection**
   - In `runtime-manager.prompt()`, extract text from the incoming prompt before forwarding to Pi.
   - Await memory retrieval with a ~200ms budget.
   - If results are non-empty, prepend:
     `## Relevant Memories`
     then one compact bullet per result: title, summary, optional short content snippet.
   - Preserve image parts for multimodal prompts; only the text portion gets prefixed.
   - Do not inject during `followUp()` while the session is already streaming.

5. **Wire all transports**
   - Register the Tauri command in `lib.rs` and the WebSocket fallback in `ws.rs`.
   - Mirror sidecar protocol types in `sidecar_protocol.rs` / `protocol.ts`.
   - Regenerate `src/lib/bindings.ts`.

## Verification

- `npm run build:sidecar`
- `cargo check` from `src-tauri/`
- `npx svelte-check`
- Manual path: insert or form a memory, send a related user message, and confirm sidecar logs / Pi request context include `## Relevant Memories`.
