# MON-105 — Auto-create active quest for meaningful user turns

Linear: [MON-105](https://linear.app/monarch-commander/issue/MON-105/auto-create-active-quest-for-meaningful-user-turns)

## Goal

Make quests exist without the captain opening the Quest Timeline tool first. When a shadow receives a meaningful task and has no active current quest, Monarch creates a root quest, assigns it to that shadow, and stores it on `agents.current_quest_id`.

This is a small bridge before MON-103 and P4: quest-close memory and coherent action narration need a quest spine, but the current product only has manual quest creation.

## Implementation plan

1. **Auto-create in the Rust prompt path**
   - Hook `AgentManager::send_command` when the command is `SidecarCommand::Prompt`.
   - Before sending to the sidecar, extract text from the prompt payload.
   - If the agent has no active `current_quest_id`, create a root quest and set it current in one DB transaction.
   - Use status `in_progress`, grade `C`, exec hint `in_context`, assignee `agent_id`, created_by `monarch`.

2. **Meaningful-turn heuristic**
   - Classification results arrive after the turn starts, so this slice cannot block on the classifier without delaying the user prompt.
   - Use a conservative local fallback at send time:
     - do not create for empty/very short prompts
     - do not create for obvious greetings/thanks/status pings
     - create for prompts with task verbs, code/file/tool language, multiline detail, or enough length to likely be work
   - Keep the classifier relationship documented: MON-82 remains advisory here; later routing can replace this heuristic when chat-shadow exists.

3. **Title derivation**
   - Derive a concise title from the first useful prompt line.
   - Trim markdown/list prefixes and cap length.
   - Fallback to `Task from <timestamp>` when no useful title exists.
   - Store a short description containing the original prompt excerpt for context.

4. **Timeline wake-up**
   - Existing QuestTimeline subscriptions are per known root; the first auto-created root has no known root id yet.
   - Emit `quest-created-for-agent-{agentId}` whenever a root quest is created for an assignee.
   - Subscribe the quest store to that per-agent channel and refresh roots.
   - Preserve existing `quest-created-{id}` behavior for known-root/subquest updates.

## Verification

- Send obvious chitchat and confirm no quest is created.
