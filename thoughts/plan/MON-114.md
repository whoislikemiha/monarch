# MON-114 — P4b Slice C: Plan panel and plan-aware timeline UI

## Goal

Make P4b visible to the captain. The backend can already persist durable
quest plans, lifecycle events, an L2 active/next plan slice, and action links
via `quest_events.plan_item_id`; this slice gives those pieces a usable
frontend surface.

## Scope

- Add frontend plan state to `questStore`: load plan items per quest and call
  the existing plan commands for add/edit/delete/reorder/start/complete/skip/block.
- Extend `QuestTimelineTool` with a lightweight flat plan panel for the active
  quest, visually separate from expanded quest details.
- Render plan lifecycle events as first-class timeline rows.
- Surface plan-item labels on coherent actions whose `plan_item_id` is set.
- Extend the Agent View Now strip with the active item and next-plan slice.
- Return `quest_events.plan_item_id` through `QuestEventRow` and regenerate
  bindings.
- Add WebSocket dispatch arms for the plan commands so browser-mode dev keeps
  parity with the Tauri webview path.

## Design Notes

- Plan items remain the intended route. Coherent actions remain actual history.
  The UI should show links between them without nesting actions inside the plan.
- V0 is flat even though the schema has `parent_id`.
- Reorder through `db_set_plan` with existing ids so item statuses are preserved
  by the backend's conflict path.
- Manual status controls are compact buttons; sidecar-originated lifecycle
  events use the same persistence methods and should update the same surface.

## Acceptance

- Captain can add, rename, reorder, delete, start, complete, skip, and block a
  plan item from the quest tool.
- Plan mutations refresh the plan panel, event log, and working-memory slice.
- Coherent actions display a plan chip when linked to a plan item.
- The Now strip shows active and next plan item titles when L2 has ids.
- `npx svelte-check` and focused Rust checks pass.
