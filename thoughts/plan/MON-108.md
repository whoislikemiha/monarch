# MON-108: P4 Slice B — Sidecar narration tools

## Goal

Expose executor narration as first-class sidecar tools so the model can describe its current coherent action without writing chatty prose. MON-107 already persists `action_transition`, `action_complete`, and `executor_decision` events; this slice makes the executor emit those events.

## Scope

1. Add custom sidecar tools:
   - `set_current_action(intent, previous_outcome?)`
   - `complete_action(outcome)`
   - `record_decision(decision, rationale?)`
2. Emit MON-107 inner events from those tools:
   - `action_transition`
   - `action_complete`
   - `executor_decision`
3. Register the narration tools alongside `suggest_memory`.
4. Add prompt guidance with general coding examples:
   - actions are meaningful chunks of work, not every individual tool call;
   - use `previous_outcome` when switching actions;
   - use `complete_action` when done without immediately starting another action;
   - use `record_decision` sparingly for explicit decisions, not hidden reasoning.
5. Add focused unit tests around tool event emission.

## Out of Scope

- Frontend rendering of nested action timelines (MON-109).
- Durable execution plans / plan item linkage (P4b).
- Hard enforcement that the model must narrate every action.
- Any timing-based guidance; agents do not reliably know elapsed time.

## Verification

- `npm run build --prefix sidecar`
- targeted unit tests for narration tool emission
- existing Rust/frontend checks as needed if shared protocol or bindings change
